# متجر جراج أبو يوسف (Abu Yousef Garage Storefront)

تطبيق متجر إلكتروني وحجز صيانة وموتوسيكلات مستعملة مبني بـ **Vue 3** (Composition API, `<script setup>`), **Vite**, **Vue Router**, و**Pinia** وفقاً لتصميم `design-concepts/shop.html` بالكامل ودون أي تغيير.

## التشغيل محلياً (How to Run)

```bash
# تثبيت الاعتماديات
npm install

# تشغيل بيئة التطوير
npm run dev

# بناء النسخة النهائية للإنتاج
npm run build

# معاينة نسخة الإنتاج
npm run preview
```

## أماكن البيانات الوهمية (Mock Data)

توجد جميع ملفات البيانات المؤقتة داخل مجلد `src/data/`:
- `src/data/products.js`: بيانات قطع الغيار والزيوت والإكسسوارات مع الموديلات المتوافقة والمواصفات.
- `src/data/bikes.js`: بيانات الموتوسيكلات المستعملة مع درجات الفحص وتقارير الـ 120 نقطة.
- `src/data/categories.js`: تصنيفات المتجر والأيقونات المرتبطة.
- `src/data/services.js`: خدمات الصيانة وأسعارها التقديرية.
- `src/data/user.js`: بيانات العميل الافتراضي والموتوسيكلات المسجلة وسجل الصيانات والطلبات السابقة.
- `src/config/store.js`: إعدادات المتجر العامة (أرقام التواصل، تكلفة الشحن، حد الشحن المجاني، وسائل الدفع).

## ما يجب استبداله بالبيانات الحقيقية لاحقاً (To Replace with Real Backend)

1. **طبقة الـ API (`src/api/index.js`)**: تم كتابة واجهة برمجية موحدة تعتمد على الـ Promises (`async/await`)، بحيث يسهل استبدال الدوال المحلية بمكالمات `fetch` أو `axios` إلى الـ REST API أو GraphQL عند ربط السيرفر.
2. **صور المنتجات والموتوسيكلات**: تم برمجة المكونات لتقبل مسار صورة حقيقية `image` وعند عدم وجودها تعرض الرسوم التوضيحية المتطابقة مع النموذج تلقائياً.
3. **بوابات الدفع الإلكتروني**: في مرحلة الربط الفعلي يمكن دمج Paymob أو Fawry بدلاً من المحاكاة الحالية في صفحة الدفع.
4. **تأكيد المواعيد عبر WhatsApp**: في صفحة الحجز (`/booking`) يتم حالياً توليد رقم حجز وتأكيده محلياً، ويمكن ربطها لاحقاً بـ WhatsApp Cloud API أو SMS Gateway.
